# Docusaurus 主题重建与项目修复设计

## 目标

将项目升级到当前稳定的 Docusaurus 技术栈，重建依赖旧版内部接口的大量主题覆盖，同时保留现有用户可见效果、文章地址和主要功能。完成后，项目应当能够在锁定的 Node LTS 环境中完成全新安装、类型检查、静态检查、自动测试和生产构建。

## 范围

本次工作包括：

- 修复当前 Tailwind 配置导致的生产构建失败。
- 修复评论内容直接插入 HTML 带来的跨站脚本风险。
- 修复评论开关、文章 `hide_comment`、友链响应判断和请求状态管理等明确缺陷。
- 升级 Docusaurus、React、TypeScript、Tailwind、Axios 及相关插件到彼此兼容的稳定版本。
- 基于新版 Docusaurus 主题接口重建现有视觉定制。
- 减少对 Docusaurus 内部组件和生成类名的依赖。
- 加入 Node 版本锁定、Lint、格式化检查、自动测试和 GitHub Actions。
- 修正仓库名称、编辑地址、版权文字、默认 Footer 链接和 README 残留信息。

本次工作不包括：

- 重新设计页面视觉风格。
- 重写评论后端或改变现有接口地址。
- 批量重写博客和文档正文。
- 删除现有的首页、博客、文档、项目、友链、搜索、PWA、评论或代码块功能。

## 用户可见兼容要求

- 保留首页 Hero、博客摘要、项目展示、技能展示和背景动画。
- 保留博客列表、文章页、标签、归档、侧边栏和分页。
- 保留文档侧边栏、前后页导航、版权声明和评论区域。
- 保留项目卡片、友链卡片、明暗主题、移动端导航和响应式布局。
- 保留代码复制、自动换行和折叠能力。
- 保持现有文章永久链接、标签链接、归档地址和 RSS 地址兼容。
- 允许内部 DOM 结构和组件实现变化，但不得产生明显的颜色、间距、排版或交互回退。

## 总体架构

### Docusaurus 核心

Docusaurus 继续负责文档、博客、路由、元数据、搜索、站点地图、RSS、PWA 和基础主题能力。升级后优先使用官方公开扩展点，只有官方能力无法满足现有展示效果时才进行主题覆盖。

### 页面与展示组件

首页、项目页和友链页继续作为独立 React 页面。可复用的卡片、动画、社交链接和提示组件保留在 `src/components`，页面只负责组合数据和组件。视觉变量集中在全局 CSS，自定义组件样式继续使用 CSS Modules。

### 博客数据

首先检查新版 Docusaurus 是否提供满足首页博客摘要所需的公开数据接口。若可以直接读取，则删除当前复制并包装 `plugin-content-blog` 的本地插件；若不能，则只保留一个最小插件，通过公开生命周期向全局数据写入文章数量、标签数量和最新文章摘要。

### 评论系统

评论系统拆分为以下职责：

- API 客户端：获取评论和提交评论，统一返回明确的成功或失败结果。
- 数据类型：定义评论、提交参数、友链和通用响应，不再使用 `any` 逃逸。
- 内容净化：将后端评论作为不可信输入，使用成熟 HTML 净化库过滤脚本、事件属性和危险协议，仅保留允许的简单格式。
- 评论列表：展示加载、空数据、失败和嵌套回复状态。
- 评论表单：完成必填校验、提交状态、成功清理和失败提示。
- 可见性策略：同时尊重全局 `commentConfig.docs`、`commentConfig.blog` 和文章 Front Matter 的 `hide_comment`。

评论接口不可用时，文章正文必须继续正常渲染。错误只影响评论区域，并向用户展示可理解的提示。

### 请求层

Axios 实例保留现有 `baseURL`、超时和携带凭证行为。请求计数不得小于零；请求成功和失败均需正确结束状态。调用方不得通过 JSON 序列化复制响应，也不得依赖互相冲突的字符串和数字状态码。

## 主题重建策略

### 优先使用官方主题

升级后先在官方默认主题下恢复全部页面和内容构建，再逐个恢复视觉效果。旧 `src/theme` 文件不会整体迁移，而是按实际差异重新判断：

- 与默认主题一致或差异很小的覆盖直接删除。
- 只增加附加内容的场景优先使用 Wrapper。
- 必须改变布局的场景才复制新版主题组件，并记录覆盖原因。
- 不引用 `@docusaurus/theme-common/internal` 等非公开内部接口，除非新版官方没有公开替代方案且风险已被明确记录。

### 迁移顺序

1. 基础布局、Navbar、Footer 和全局样式。
2. 首页及其展示区块。
3. 博客列表、文章页、标签和归档。
4. 文档内容、版权声明、评论和分页。
5. 代码块复制、换行和折叠。
6. 项目页和友链页。
7. 移动端、明暗主题和动画细节。

每完成一个区域，立即运行相关测试和生产构建，避免在最后集中处理兼容问题。

## 依赖升级策略

- 使用同一版本系列的 Docusaurus 核心、预设、主题和官方插件，避免混用版本。
- 选择 Docusaurus 支持的 Node LTS 版本，并通过 `.nvmrc` 和 `engines.node` 锁定范围。
- 先升级 Docusaurus 及其官方插件，再升级 React 和其余前端依赖，便于定位不兼容来源。
- 删除同时出现在 `dependencies` 与 `devDependencies` 的重复构建依赖。
- 删除不再使用的插件和包，不为尚未使用的能力增加新依赖。
- 保留 Algolia 搜索公钥、统计 ID 和备案信息；它们属于客户端公开配置，但应移除错误或过期的品牌文字。

## 数据流与错误处理

### 评论加载

页面决定评论是否可见后挂载评论组件。评论组件进入加载状态，API 客户端请求数据；成功时显示评论或空状态，失败时显示错误提示和重试入口。任何后端内容在渲染前都必须经过净化。

### 评论提交

表单先进行用户名、邮箱和内容校验，再进入提交状态。提交成功后重新获取评论并清理表单；提交失败时保留用户输入并显示错误信息，避免用户内容丢失。重复点击不得产生并发提交。

### 友链加载

友链页请求分组数据，成功时按“我的工具组”和“我的友链”展示。返回为空、状态码异常或请求失败时显示稳定的空状态或错误提示，友链申请区域仍可使用。

## 测试与验证

### 自动测试

引入适合 React 和 TypeScript 的轻量测试环境，覆盖以下行为：

- 评论净化会移除脚本、事件属性和危险链接，同时保留允许的换行和简单文本。
- 评论全局开关和 `hide_comment` 能正确决定是否渲染。
- 评论提交失败时保留表单内容并显示错误。
- 友链异常响应不会解引用空对象。
- 请求计数不会变为负数。
- 首页博客数据适配器能返回稳定的数据结构。

### 构建验证

完成标准要求以下命令全部成功：

```text
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

### 页面回归

至少验证以下页面：

- `/`
- `/blog`
- 任意博客文章页
- `/docs/intro`
- `/project`
- `/friends`
- `/blog/archive`
- 任意标签页

检查桌面端、移动端、明亮主题和暗色主题。重点比较 Navbar、卡片、文章正文、代码块、评论、Footer 和页面间距。

## 持续集成

GitHub Actions 在受支持的 Node LTS 版本上执行依赖安装、类型检查、Lint、测试和生产构建。任何一步失败都阻止合并。CI 不负责部署，也不引入新的云服务。

## 完成标准

- 全新克隆后按 README 可以安装和构建。
- 类型检查、Lint、测试和生产构建全部通过。
- 当前核心页面、URL 和用户可见功能得到保留。
- 评论内容不能注入可执行脚本、事件属性或危险协议。
- 评论开关与文章 `hide_comment` 均有效。
- 评论和友链接口失败不会破坏正文或整个页面。
- 旧主题覆盖被显著缩减，保留的覆盖基于新版公开接口并有明确用途。
- 配置和文档中不再包含错误仓库地址、他人品牌文字或未完成占位内容。
- 后续提交可由 GitHub Actions 自动发现类型、测试和构建回归。
